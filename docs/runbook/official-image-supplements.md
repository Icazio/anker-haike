# 官方图表文字知识的维护

当前采用先核对图表、再补充文字的方案。来源文件为`data/official/qa_supplements.yaml`，与工作簿生成的`qa.yaml`分开；后者不能手改。长期方案及取舍见[方案与迭代顺序](../planning/2026-10-14-1716_official-image-knowledge/方案与迭代顺序.md)。

## 添加或更新一条知识

1. 打开官方页面并实际查看对应型号图表，核对图例、表头与行列关系。保留本机原图及其SHA-256；不要只凭图片标题或自动识别结果填写内容。
2. 在补充源中新增唯一`supp-`前缀ID，填写标题、型号列表、品类、适用范围、英文事实摘要和来源。来源包含官方页面URL、图表位置、原图SHA-256、核对日期及核对状态。`agent_source_checked`表示代理目视核对，`human_checked`表示人工核对，不代表厂家批准。
3. 一条知识保留完整条件。例如主机绿灯的闪烁和常亮两种定义放在一起，范围注明不适用于充电盒。每条尽量短，不把表头与含义拆开。当前补充机制用于解释类知识，不从文字自动推导维修动作。
4. 运行相关测试和`make lint`。严格字段校验会阻止无来源、错误型号格式、错误指纹和重复ID进入索引。
5. 执行`make kb-ingest KEEP_LEGACY=1`。这是项目知识源同步入口，会按当前完整源集合删除不再存在的条目；运行前先确认没有其他会话修改来源。`KEEP_LEGACY=1`保留旧库，本次不做清理。
6. 验证条目解析成功、来源元数据存在、正确型号可检索、其他型号及未确认型号不可用，并通过产品咨询实际检查模型收到完整定义和适用范围。
7. 正常发布新代码及数据后加载新的业务进程。知识适配器会缓存允许检索的条目列表；已有进程不会因入库自动刷新。只重启旧镜像不能加载本机新增代码和源文件；需要按发布流程更新镜像，或用本机源码启动独立开发服务验证。

## 版本行为

补充条目的正文、型号、范围和来源共同生成内容版本，格式或注释变化不改版本。原工作簿条目保留原版本；只改一条补充不会重建全部赛题知识。总知识版本同时包含工作簿和补充集合版本，加入、修改或移除补充均可反映到总版本。

入库正文保留标题、适用范围和完整含义；出处单独保存为知识元数据，避免长URL污染检索。`doc_id`可定位回本地源及官方页面。自动解析图片和回答时实时读官网图片属于后续方案，当前没有启用。

## 最小验收

- T8D04主机绿灯闪烁与常亮定义都进入回答证据。
- 不把同一规则用于充电盒、其他型号或其他颜色。
- 静态照片只证明拍摄时亮着；用户未提供时继续询问闪烁状态。
- 检索不足时只描述当前证据范围，不断言官方没有说明。
- 相同源重复入库不替换知识；补充改变时更新条目和总版本。
