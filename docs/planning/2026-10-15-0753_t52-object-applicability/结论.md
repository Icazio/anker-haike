# T52 开发与测试结论

> 2026-10-15 官网复核勘误：下文的测试证明了阻止串对象，不证明“直接转人工”已充分服务用户。官网存在充电盒无法充电/充满的相关文章，厂家快速指南也有盒或泵不工作的通用排查及磁吸直充办法。当前实现没有给 T52 提供临时恢复泵供电的路径，业务完整性仍不足。不得将“尚未确认盒输入专用维修流程”扩大为“官方没有解答”，也不得断言旧分支所有步骤都无帮助。来源和具体判断见 [复评记录](addendum.md#官网复核勘误与业务目标补充)。

**建议保留 B 方案：用明确的对象关系约束官方流程的适用范围。已经接入正式源码，本地测试有效；暂不需要图数据库。**

T52 的关键改进是：客户说“盒自己充不进电，所以泵充不了”，系统识别为盒输入故障及其后果，不再自动进入泵不开机流程。原实现把说明缺口并转人工作为终点；官网复核后，应补充有依据的基础检查及临时恢复泵供电的选项，并分别追踪盒故障与使用需求，不能把临时能用当成盒已修好。

## 本次实际做到什么

| 检查项 | 本轮结果 |
|---|---|
| T52 原文、重复、中文、英文改写 | 4 场均进入正确知识缺口分支，没有泵操作卡；最后提示修订后原文再测仍正确 |

| 磁吸线直充失败 | 正常执行直充接口流程，没有改去修盒 |
| 左泵坏、右泵正常 | 左右侧区分，没有相互抵消 |
| 用户把故障从盒改为泵 | 旧盒事实失效，改走泵不开机流程 |
| 用户把故障从泵改为盒 | 停止旧泵步骤；售后结案文案仍有不足 |

| T53 充过电仍不开机 | 中间出现错误事实与错误追问；最后连续两场语义与选路均正确 |
| 无吸力 T54、T55 | 流程保留；T54 另补跑至第 8 轮售后收尾 |
| T48 绿灯 | 补充型号及常亮状态后，使用已入库灯态知识正确回答；不再声称官方没有说明 |

程序侧共 **270 项相关测试通过**，`make lint`、`git diff --check` 通过。测试包括故意让模型以高置信度选错、旧步骤重新检查、事实更正、左右侧、跨品类和完整上下文保护。

真实模型与知识库：一次 19 场边界回归保存 64 轮；最后语义修订后补测 6 场保存 29 轮；T54 收尾补测 1 场保存 8 轮。合计这三组 **26 场、101 轮记录**，覆盖 9 个原始工单及衍生对话。这是测试场次，不是 26 个不同的官方工单，更不是 63 案全量验收。

## 应该分别归到哪里

| 类别 | 这次确认的事情 | 后续处理 |
|---|---|---|
| 系统本身要改 | 仅靠选案提示无法阻止串对象；旧计划可能在更正后继续 | 已加选案前、选案后、发卡前检查与事实失效处理 |
| 意图/事实理解不准 | T51 把续航当充电；T53 把尝试充电当充电失败 | 已补关系定义和中英文边界；模型仍可能误解，需要持续测多样表达 |
| 知识库缺覆盖 | T52 有相关充电材料，但没有确认适用的盒输入维修流程 | 获取并审核该流程后补入，更新适用范围；不能拿泵流程代替 |
| 知识执行链路 | T44 先排障的要求卡在售后材料收集之前，尚不能据此证明已找到适用知识却没执行 | 优先修任务切换与暂时缺材料时的排障入口，不能只补知识 |
| Agent 边界 | 无官方适用流程、缺购买凭证或故障资料 | 明确说明并转人工/索取必要资料，不编造维修结果或换货承诺 |
| 图片识别 | T48 原图能见绿灯和裂纹，单张照片不能证明闪烁状态 | 图片观察与灯态知识分开；必要状态由用户补充确认 |
| 官方口径 | T53 保内出现、过保报修如何处理；部分官方英文部件词不自然 | 需要官方政策/资料复核，不由关系模型擅自改政策和术语 |
| 运行稳定性 | 主位 9 秒限制导致连续超时 | 已按实测扩时并统一回执；最坏等待时间相应增加 |

## 容量调整是否合理

固定输入实测约 5012 token、schema 3263 token，护栏调整为 5500、3600，约留 10% 余量。生产输入总容量本身仍够用，保留默认 16000、理解任务 32000；完整事实、风险和历史保护测试未放松。

主位模型超时调整到 15 秒，理解/选案预算各 22 秒，文字轮总时限 45 秒、含图轮 60 秒。19 场回归首轮耗时中位数约 **16.4 秒**，最大 **38.7 秒**（含图 T53），T52 原文约 **12.4 秒**。该小样本混合了不同任务和运行环境，不能据此推算全系统性能，也不能宣称扩时使系统变快。

## 仍未解决的事项

1. **T44 优先级切换**：客户要求先排障，系统还在要订单，是下一项明确的程序问题。
2. **T53 结案后的纠正答复**：动作已停止，但只说“未解决结案”没有解释新问题为何缺资料；官方迟报保修政策也未确认。
3. **关系抽取稳定性**：检查规则只约束已识别关系，模型漏抽、错标或因果引文不完整仍有风险。几次成功不足以给出总体准确率。
4. **覆盖范围**：目前审核 12 个相关官方计划，没有完成所有品类和所有案例的关系标注。

代码尚未提交或部署。真实评测中的业务写入使用测试内存服务，没有向真实客服创建工单。
