# Claude再次修改后，63案实测结果

**有几处明确改善，但这一轮的整体合理案例数没有提高。** 主轮42案处理合理、20案需要改进、1案官方口径待核；上轮是43、19、1。这里的合理是已观察服务过程合理，不表示设备修好了。

主轮于2026年10月12日20:25:26—20:28:19运行，另做14个独立补测。总计77个新会话、164轮交互、2261条事件；63条原文及10个附件全部核对。主轮与补测没有接口、采证或模型最终失败记录。180项相关自动化测试、make lint通过。

**测试的是当前工作区代码。8000端口仍运行旧镜像，本轮另外在18000启动临时服务，使用独立项目测试库，没有构建或部署。** 相同模型配置、相同知识服务和原始输入；主轮及补测期间代码与进程均未变。临时进程Python 3.14.7、旧容器3.12.14，核对的8个核心依赖版本一致，因此这是实际行为对比，不是完全相同运行环境下的严格因果实验。

## 为什么修了，数字却没有上升

| 变化 | 案例 | 实际发生的事 |
| --- | --- | --- |
| 2案由需改进变合理 | T31、T60 | T31恢复出厂前提醒可能丢地图；T60先问具体症状，不再把希望正常清扫当成清洁效果差。 |
| 2案由合理变需改进：流程波动 | T27、T52 | T27主轮漏掉客户已检查的承接说明；T52主轮把盒自身充不进电带到盒给泵充电。两者两次补测均正常，但不能覆盖主轮。 |
| 1案由合理变需改进：视觉 | T42 | 上轮把基站写成背景，本轮把基站写成画面主体；前景其实是脱落塑料件和机器人底部。售后路线未变，识别缺陷仍需记录。 |
| 其他58案综合结论相同 | 包含T37、T40、T51等 | 有的局部变好，但同案其他问题还在；有的只是措辞或停点变化。 |

因此是43＋2－3＝42。36案对客文字和卡片相同、27案发生变化；视觉内部摘要另行核对，T42虽然对客回复相同，内部识别发生变化。单轮差1案不足以证明整体能力显著下降，也不能把修改项单测通过说成整体已提高。

## 剩下的问题，分别谁来处理

下表允许一案多类，数量不能相加。Agent边界指系统应该等待客户事实、材料或人工决定，并非缺陷。

| 类别 | 案例 | 通俗解释与下一步 |
| --- | --- | --- |
| 系统本身要改 | T27、T32、T34、T37、T40、T48、T52、T53、T61 | 已知事实要留住；不能把满水仍告警解释为普通缺水；完整知识需要稳定选中；多个问题不能漏掉。T53先补官方争议口径。 |
| Agent边界 | 37案带边界标记，详见案例索引 | 未知错误码、灯态、文章检查结果，需要客户回答；保修、补发和库存要人工决定。不能把这些停止统一判成知识库不执行。 |
| 知识没有有效用起来 | T40、T61 | T40有完整替代资料却走缺口条目；T61问了提前两小时，但仍没独立处理清扫记录丢失。都不是证明完全没有检索。 |
| 知识资料缺口 | T13、T34、T40、T48 | 5116、历史地图恢复、缺链接条目、绿灯含义，分别需要补齐或核实；不要让Agent猜官方答案。 |
| 意图或症状不准 | T52 | 盒自身不能充电与盒不能给泵充电是两件事；选方案前先保住故障对象。T60本轮已改善。 |
| 图片识别与使用 | T30、T42、T48 | T30/T42前景主体不准；T48识别到灯，但漏裂纹，回答仍没给绿灯问题有效下一步。 |
| 官方口径问题 | T32、T51、T53 | 临时贴胶带的有效性和换新措辞、乳泵部件及蓝牙说明、保内故障但过保申报，分别需要厂商确认。 |
| 语言表达 | T6、T13、T18、T20、T21、T22、T28、T36、T37、T43 | 荷兰语、法语、德语、西语客户仍收到英语。有8案当前主要只剩语言问题：T6、T18、T20、T21、T22、T28、T36、T43；修复语言有清晰收益，但不能预先记成通过。 |

优先处理T52故障对象、T27事实承接稳定性和T40完整资料替代，再修视觉主体与多语输出。T31、T51已生效的改动应保留。T37要改正文适用解释，单纯引用“水箱满”还不够。
