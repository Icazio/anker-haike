# 问题分别由谁处理

这里的“系统问题”包括模型理解、知识使用、流程控制和回答生成；“Agent边界”指系统当前没有权限、工具或事实依据继续。一个案例可同时有多个因素，下面按责任解释，不把标签数量当失败案例数。

## 1. 系统流程本身要改：有动作，就不能没等结果便结束

**T20：** 客户无法定位，系统选中rv-0090，输出重建地图并重新开始任务，内部结果却是“解释完成”，没有操作卡。首次、补测一致。由此可确认，资料内容存在、建议也发出了，但反馈环节没有建立。[首次记录](逐案记录.md#t20) · [补测](补测记录.md#t20)

**T43：** rv-0271原资料第四项明确要求重启路由器和设备、重新配网。前三项有操作卡，第四项只在最后一句出现，紧接着就说排障完成。两次都没有第四项反馈。首卡还把链接显示成空尖括号。[首次记录](逐案记录.md#t43) · [补测](补测记录.md#t43)

需要让“操作建议”和“解释说明”有明确区别。凡需要客户实际做某件事验证结果的内容，都必须留下可回复的步骤；只有已收到结果或客户主动放弃，才能进入下一节点。链接显示是另一个较小的呈现问题，应单独处理。

以上是本轮从输出和内部状态确认的错误环节；本次没有修改或重跑编译器单元实验，不把早前报告里的代码根因实验冒充本轮结果。

## 2. 意图理解不准：词语相近，问题对象或时间方向却不同

**T52：充电盒充不进电，不等于泵不能开机。** 首次只是复问盒是否充电；补测直接选bp-0114“吸奶器不能开机”，随后泵复位、换盒、查接触、磁吸线、问到货时泵按钮损坏。即使其中某项能帮助临时给泵供电，也没有解释它怎样处理盒自身的故障，主线已经偏移。[补测完整过程](补测记录.md#t52)

**T61：提前启动，不等于到点无法启动。** 首次承认没有确认适用资料，并保留提前两小时和无记录两项问题；补测却问计划开始时是否低电量。这个问题沿用了相反时间方向的排障思路，不能用“都涉及计划清扫”解释为匹配。[首次](逐案记录.md#t61) · [补测](补测记录.md#t61)

系统应在选知识和发追问时都核对三个事实：**哪一个部件、发生了什么、在什么时间或条件下发生。** 针对充电，还应明确谁给谁供电；针对调度，应区分提前、延后、未执行。这个核对是必要约束，不应只靠回答生成阶段润色。

正向对照是T40和T50：T40本轮两次都明确查清洁剂；T50没有把“能用”擅自理解成“不能用”。所以不能笼统说系统一直认不清意图，也不能以一次正确回答证明稳定。

## 3. “知识库不执行”需要拆开判断

知识库负责提供资料，真正发步骤、等待结果的是对话系统。本轮没有发现知识库服务请求失败直接导致的错误；这只覆盖已发生的请求，不证明召回质量全部合格。

| 情况 | 本轮例子 | 正确归因 |
| --- | --- | --- |
| 找到了正确资料，但操作没闭环 | T20、T43 | 流程执行问题 |
| 用了相近资料，却没核对对象或条件 | 补测T52、T61 | 适用性选择及追问问题 |
| 官网有图表，但系统没用到其文字含义 | T48 | 知识覆盖/图表利用，加上回答范围过度断言 |
| 无法确认适用答案，承认未知并转人工 | T13、T34；首次T61 | 可以是合理边界，需继续核实资料 |
| 有资料，但要先确认客户是否做过 | T40 | 当前等待事实合理，未测后续不能算执行失败 |

**T48的直接证据：** 系统两次都称官方没有绿灯解释；官网S1 Pro图表有绿色闪烁与常亮的定义。本轮查看了该图表，且在本地T8D04适用问答文本中未找到green定义。可以确认系统本轮没有利用到正确图表信息；究竟应在资料导入、图片文字提取还是外链读取处修复，需进一步定位，不能仅凭结果断言具体代码行。[官方图表所在页](https://service.eufy.com/article-description/What-does-the-status-of-each-LED-indicator-on-the-eufy-Breast-Pump-E10-S1-S1-Pro-representWhy-does-the-eufy-Breast-Pump-s-flange-stick-to-my-breast)

更合理的回答应先说明“该型号官方图表分别定义了闪烁和常亮”，再请客户确认状态；裂纹作为另一个观察单独处理。无法判断闪烁时，可以不下单一结论，但不应把系统获取资料的限制说成厂家的限制。

T40的外链也说明为什么不能只看关键词：官方要求先标记清洁剂液位，完成规定用水量后再比较消耗。是否不出液有测量前提，不能由“看起来下降慢”立即断言损坏。[官方清洁剂检查方法](https://service.eufy.com/ie/article-description/How-do-I-use-eufy-cleaning-solution-with-my-S1-Pro)

## 4. 图片识别问题：看到了什么，与推断了什么分开

**T42为明显错误。** 原图可分为手持塑料件、后方机器人底部、背景基站。系统两次写“手持机器人本体底部”，并将定位柱、触点、标签等细节混在一个主体下。后续售后方向来自客户已描述物理损坏，所以仍然合理；但错误图片证据可能影响后续部件判断，必须修。[原图](../../../data/official/attachments/T42.jpg) · [内部状态](state/run/T42.json)

**T14、T30为内部证据瑕疵。** 单张照片能确认红灯亮起，不能确认一直亮着。两案内部原始视觉字段分别写了常亮；本轮未据此改变客户路径，故列瑕疵，不与T42等量处理。应限制静态图片输出时间状态。[T14状态](state/run/T14.json) · [T30状态](state/run/T30.json)

**T20本轮没有复现“基站缺失”。** 两次都识别有基站、未见机器人本体。不能把旧轮读图错误挪到本轮。

**T48两次都没有把静态图断言为常亮。** 绿灯、黄灯、裂纹被记录了；主问题是没有利用官网图表。首次文字把绿灯描述在电源键上方，补测描述为左侧；本轮优先关注不影响灯身份的对象与时间证据约束，不把每个方位差异再计成一个失败案例。

T38、T46、T53、T55都是订单或发票截图，系统将其识别为单据，没有当作现场故障证据。T45因烫伤描述优先转人工，未执行图片诊断；不能宣称它的购买截图识别已通过。

## 5. 正常的Agent边界，不应该靠模型猜过去

- T7没有唯一订单标识；T47没有配件独立订单。等客户补充。
- T19、T26、T36、T38、T46、T57所问是现场事实。等客户确认。
- T1等调查申请、T5等补发申请停在确认卡。本轮没有替客户提交，更没有实际联系承运商或仓库。
- T44、T49、T55、T59更换要核保和材料。系统可以整理，不可假装已批准。
- T9暂停发货、T63查库存缺少当前工具权限。转人工合理。
- T45报告烫伤，停止常规排障并转人工合理。

边界仍要解释完整。T63说先采购后排障，却只向客户说明采购已转交，内部另一任务仍待处理，应明确是否一并转交。T41首次和补测都还在问事实，不能按未测的后半程判定已经漏掉配送；可以改进为同步收售后单号，减少等待。

## 6. 官方口径问题：不要全写成“缺知识”

| 类型 | 案例 | 需要官方确认什么 |
| --- | --- | --- |
| 当前导入资料缺直接答案 | T13 | 5116通信异常的具体定义和处理；全部本地问答无5116匹配 |
| 恢复能力没有直接说明 | T34 | 维修后旧地图、历史记录和可恢复地图之间的关系 |
| 操作条件或动作表达 | T15、T26、T32、T56 | 拆盖前准备；翻转摇动幅度；胶带临时方案范围；准确开机按键 |
| 部件和充电对象 | T51、T52、T54、T55 | 盒自身充电与盒给泵充电；磁吸直充适用条件；软管等名称是否适配型号 |
| 政策例外 | T53 | 保内发生故障、过保提出申请时，是否受理及所需证据 |
| 静态业务数据需核对 | T1、T2、T4、T10、T47 | 实际收到物品与包裹记录、查询时点、整机与配件订单关系 |
| 特殊场景需要深化 | T37、T41、T61 | 满水仍误报、没拖地却烘干报警、提前清扫且无记录；目前未证实厂家完全无资料 |

充电盒官网页面本身也把泵放入盒、泵充电状态和盒充电时长放在同一篇中，标题与正文对象容易混淆；系统仍须区分客户实际问哪一个，不能把来源写法作为选错对象的理由。[官方充电盒说明](https://service.eufy.com/article-description/The-charging-case-cannot-charge-be-fully-charged)

T53同时有两方责任：官方要明确例外政策；系统要准确承接客户申诉，不应默默忽略“故障发生在保内”。这里不替官方承诺免费处理，也不把按赛题默认期限得到的结果扩展为法律结论。

## 7. 语言和表达是系统问题

10案主要回复语言与客户不匹配：T6、T13、T18、T20、T21、T22、T28、T36、T37、T43。回复翻译必须覆盖操作卡、选项、风险提示和售后文案。只翻译一句开场白没有用。本报告给出中文是为了方便复核，不能因此说产品已支持中文或客户语言。

T5/T8的重复状态、T16/T29/T52的已知事实承接、T53的迟报诉求、T56的按键描述、T63的任务接续，都是本轮可以明确指出的改进点。每项应围绕一个可验证行为修改，再用相同原文复测。

## 建议的验收标准

1. T20/T43每项实际操作都有反馈入口，收到结果前不宣称排障完成。
2. T52只围绕盒受电问题选步骤；若建议给泵临时充电，明确这是替代办法，不冒充盒故障原因已找到。
3. T61保留提前两小时与无记录两项，不再沿用无法按时启动的问题模板。
4. T42能分别标注前景件、机器人和基站；T14/T30不从单帧推断常亮。
5. T48能引用绿灯图表，区分常亮/闪烁；资料不足时准确限定为本次检索范围。
6. 多语言案例的卡片与说明保持客户语言；已做检查先承接，重复时说明具体复核点。

这些是必要改进。扩大模型、增加复杂的多任务调度、全量外链抓取属于可选实现，不能先当作已证实的解决方案。
