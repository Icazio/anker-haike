# 问题该怎么处理

[回到整体结论](先看这里.md) · [63案中文过程](63案中文过程.md)

这里区分已观察到的行为与尚待确认的原因。修改建议没有在本轮实施；不把推测写成已定位的代码缺陷。

## 1. 先恢复默认模型调用

**问题：**当前默认首轮理解在63案全部失败。部分规则能兜底，但故障描述、多请求和已做步骤大量损失。最终独立串行T22、T31、T52也失败。

**具体过程：**串行日志显示首选deepseek-pro约15秒超时，再尝试deepseek；整个理解调用约22秒后报错，配置中的后续Qwen未获得执行机会。T52还收到一次503服务繁忙。输入估算约7408—7609 tokens，低于32000输入预算；这3次没有输入截断证据。此处tokens是模型的文本计量单位。

**处理：**运行负责人检查服务端响应、超时预算和切换策略，让可用候选在总预算内真正有机会执行；失败时保留客户原话并给明确的暂时故障说明。需要区分服务端繁忙、响应太慢和本地编排，不根据一次503宣称服务商全局不可用。

**验收：**默认配置重新跑相同输入，首轮理解成功；每次失败应有可核对的尝试记录，后续可用模型能够接手。HTTP返回200、事件以done结束不等于模型或业务成功。

## 2. 知识库问题必须按发生在哪一步拆开

检索是“把可能有用的资料找出来”，采用是“选中与当前情况匹配的方案”，执行是“把步骤交给用户并按反馈继续”。三步不能混算。

| 类型 | 本轮证据 | 应由谁处理 |
|---|---|---|
| 找到了直接对应内容，却没采用 | T55 evidence含bp-0102“咔哒响但没吸力”，方案被记为无有效证据；两次均转人工 | 系统证据关联与模型输出约束 |
| 找到正确充电内容，却选了返航流程 | T31 rv-0473、rv-0363均在证据中，相关候选被拒，后面选rv-0423；复测正常 | 系统引用关联及方案适用检查 |
| 检索结果偏离同义输入 | T43西语离线主要取回悬空、受困、返航；T39英文能走离线追问 | 多语言查询与召回质量；不能只改最后一句回复 |
| 有相关内容，但还不够确认适用 | T20定位失败、T41未拖地却烘干报错、T62不走直线 | 补关键事实、检查适用条件和检索；不能强套相近流程 |
| 当前材料尚无精确处理路径 | T13错误5116、T34维修后历史地图不可用、T52充电盒自身输入、T61提前两小时兼缺记录 | 知识负责人确认覆盖；必要时新增官方条目 |
| 已有后续求助，却被服务流程结束 | T53复测说继续排障，立即未解决结案；T44明确换优先级仍被订单材料卡住 | 服务流程与请求管理 |

T55最有区分力：本轮检索证据中的bp-0102编号为`cac6104f-5d58-4c1c-b110-21a4d9ca493e`，生成候选却引用另一编号，校验输出`no_evidence:qa_bp_0102`。这支持“证据引用关联失败”，不能仅凭此断言具体是哪一行代码产生了错误。

修复不应删除证据校验。校验挡住无效引用本身合理；应让生成的引用来自本轮允许集合，无法关联时受控重试或说明未确认，不要错误归因为官方没有资料。

**验收：**T55直接相关内容能成为可执行候选；T31将“已在基站不充电”与“回不到基站”区分；未采用时记录准确原因。T20、T41、T62若仍不能确定，应问具体区别或诚实交接，不为提高步骤数而强行执行。

## 3. 意图与事实：不要只抓关键词

**T56：**用户说S340离线，又质问“这就是你们的保修？”系统只建立保修查询。应同时保留离线求助；反问服务质量不等于只查保修期限。两次对照相同。

**T41：**“没有运行拖地、也没有需要烘干”在交接摘要中变成已做操作`run mop cycles；needed any mop drying`。完整原文虽仍在记录里，但接手者可能只读摘要。应校验事实极性，即一件事是发生、未发生，还是尚不确定；摘要必须与原话一致。

**T44：**“暂时没订单，先处理触针”没有改变任务顺序。物理损坏可能确实只能售后，但需要直接解释限制与下一步，不能重复索要同一材料。

**验收：**T56同时保留离线和保修背景；T41摘要含“未运行拖地”；T44回应新要求，或说明为什么无法自行排查。T50是正向参照：左泵能工作不能改成左泵坏了。

## 4. 售后流程：过保不等于客户的其他请求消失

**问题：**T53明确“更换或维修”，并称故障在保内发生。首次直接过保结束；复测承诺继续排障后仍立即结束。T51虽然走完排障，但失败后也未给新的服务接续；T29排障后过保退出。

**系统应做：**分别保存免费更换资格、排障状态、维修诉求；有未处理请求时不能只因为免费更换被拒就把整件事结束。公开说明是否提供人工核实或付费维修入口。

**官方应定：**保内发生但延迟申报是否可受理，哪些地区有付费维修，哪些损坏只供配件。这里没有足够依据替官方或当地法律判断资格。T53发票2024-12-13，提交2026-09-27，与口述24个月也有出入，应核对。

**验收：**T53的维修请求获得明确去向，回复不再出现“接下来排障”紧接“已结案”且无步骤的矛盾。

## 5. 图片：分清看到了什么，以及据此能判断什么

本批10案有本地附件。其中5张是产品／现场图，5张是发票或购买截图。T45因安全文本直接分流，未执行故障视觉识别；不能把“有附件但没识别”算成图片正确。

| 案例 | 人工查看附件 | 模型表现与结论 |
|---|---|---|
| T14 | 机器人停在基站前、红灯条 | 对象基本正确；硬件判断来自错误码，不能只凭红灯 |
| T20 | 空基站，没有机器人本体 | 识别正确；不能据此判断定位模块坏了 |
| T30 | 机器人顶部红色环形灯 | 基本正确；仍需结合E4和刚换边刷 |
| T42 | 手拿一块脱落塑料件，背景机器人底面 | 默认、对照、复测均把两者合并，明确图像关系错误 |
| T48 | 电源附近绿灯、黄色灯列、外壳裂纹 | 可见内容识别有价值；静态图不能确定闪烁。补型号与常亮后灯义回答正确 |
| T38、T46、T53、T55 | 发票或订单截图 | 类型识别正确，不能当作故障实物图；没有因此证明全部文字识别字段都正确 |
| T45 | 购买截图 | 安全流程优先，未做故障视觉判断 |

**处理：**图片描述将前景零件、背景设备及部件归属分开；不确定零件名称时先保留描述。视觉接口返回成功只说明调用成功，不能证明识别内容正确。

以下核对了当前仓库完整条目。建议由知识负责人确认后更新，系统不能凭通用经验擅自改成另一套维修操作。

这类问题不能简单统计为“Agent幻觉”。应同时评价来源是否可靠、适用对象是否正确、呈现是否完整。

## 7. Agent该停下来的边界

合理停止包括：T7没订单标识；T19、T26、T36、T46等等待现场事实；T45安全问题人工处理；T47未查到独立配件运单；T50客户未说清哪个部件坏；T58只有情绪没症状；T59跨型号换货需授权。

Agent不能接触实物，不能替客户证明清洁、重启或更换已经有效；也不能据一个模型生成的“已转人工”断言真实客服接单。测试只确认内存案件状态与交接内容。

T41配件进度、T63清洁差与防缠绕仍保存在待办，不应描述为彻底遗忘；但当前回复也未明确这些请求下一步由谁处理，应改进交接说明。

## 8. 体验问题单独改

荷兰语T6、T13、T18、T20、T22、T36、T37，法语T21，德语T28，西语T43的对照输出主要为英语。它们有的业务方向正确，但服务语言不匹配；默认失败兜底有时又切成中文。

T16、T27、T37、复测T31虽然复述了已做检查，仍要求重复执行。应该区分“已做且具体方法一致”“客户只笼统说做过”“新增的不同检查”，再决定跳过、确认或继续。

**优先级：**先恢复默认调用，同时修T41事实错误、T31／T55知识关联、T53／T56诉求与流程、T42图像归属、T57操作适用性；随后处理语言、重复步骤和交接表述。官方操作说明与售后政策并行核实。
