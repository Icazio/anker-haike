# 63个官方案例：这轮测试说明了什么

测试日期：2026年10月13日。重新运行63案，并对重点问题增加11次重复测试，共74个独立会话、148轮交互。每案都有中文过程、原文、系统实际动作和独立判断。

**主要结论：基础流程已经能用，但还不能把“走完流程”当成“理解正确、问题解决”。最需要改的是：不改写客户原意、不遗漏并列诉求、真正收集条件信息，以及图片描述保持证据边界。**

## 先看整体结果

这里按“本轮业务处理是否合理”把63案分成三个互斥组：

| 判断 | 数量 | 怎么理解 |
|---|---:|---|
| 当前处理路径可继续沿用 | 51 | 查单、排障、追问或转人工的方向合理；可能仍在等客户资料，不表示已经修好。 |
| 系统核心行为需要修改 | 9 | 已观察到理解、条件执行、多诉求或图片问题。T12、T31、T34、T41、T42、T48、T50、T53、T57。 |
| 主要需要补官方知识 | 3 | T13缺5116指导；T37满水误报的指导薄弱；T61没有覆盖提前启动及记录丢失的适用答案。 |

**另有10案回复语言不匹配**：T6、T13、T18、T20、T21、T22、T28、T36、T37、T43。客户使用荷兰语、法语、德语或西班牙语，系统使用英文。它与上述业务判断分开统计：8案业务路径合理，2案同时缺官方知识。若把语言也算作系统改进，共涉及19案，即9案核心行为问题加10案语言问题；这19案并非新增案例。

本轮没有接口调用失败，没有最终模型调用失败；T31有一次输出字段过长，重试后成功。技术上跑通不等于业务上答对。

## 这9案具体要改什么

“系统本身”指能通过输入理解、状态记录、流程或图片处理改进的问题。模型有时答对，不足以证明这部分已经稳定。

| 案例 | 客户说什么 → 系统实际做什么 | 为什么需要改、应怎样改 |
|---|---|---|
| [T12 缺水后只吸尘](conversations/T12.md) | 客户问缺水切换状态 → 找对知识，但只给补水动作，一次“未解决”后收质保材料。 | 官方知识还解释无基站楼层缺水时的保护机制。应先解释，再确认楼层、水箱和补水后的状态，避免把正常机制直接当故障。 |
| [T31 已擦触点仍充不进电](conversations/T31.md) | 客户已说擦过 → 第3张卡仍直接要求擦触点，没有承接已有事实。 | 保留“已做过”状态，只补问是否两端都擦净。恢复出厂前的地图删除提醒本轮已经有，不能把这一项改善当成全案已好。 |
| [T34 找回维修前的旧地图](conversations/T34.md) | 历史里能看到旧图但不能用 → 承认无法确认恢复，然后继续重建地图，最后收通用质保材料。 | “找回旧图”和“重建一张”不是同一目标。应提供旧图核查路线，收维修单、设备和历史线索；是否接受重建由客户决定。两次均如此。 |
| [T41 注水、烘干提示、配件物流](conversations/T41.md) | 同时说注水没修好、未运行拖地却报烘干失败、询问替换件物流 → 只追问烘干错误码，说稍后查物流。 | 问错误码合理，但物流被一起卡住，注水异常也没进入并列检索。应同轮收错误码和订单／售后案件号，并保留三个诉求；原文plugs的具体部件待核实。两次均如此。 |

| [T48 绿灯是什么意思](conversations/T48.md) | 一张静态泵体照片 → 说绿灯“常亮”，随后又问是否常亮；补测还出现灯位描述变化。 | 单张照片只能证明拍摄瞬间亮着。先问闪烁、出现时机和朝向，再用对应型号灯态表解释；不能根据裂纹猜绿灯原因。 |
| [T50 左边能工作](conversations/T50.md) | 原文“left one does work” → 内部改成左侧不能工作，再问哪个部件充不了电。 | 肯定句被改反，知识候选又带入充电症状。先中性问哪一侧、具体什么问题。两次补测答对，说明存在不稳定，主轮错误仍成立。 |

## “知识库没执行”要分清四种情况

知识库是供系统查阅的资料；系统负责判断资料是否适用，并把它变成解释、问题或操作。看到没有操作卡，不能直接判定知识库失效。

| 实际情况 | 本轮例子 | 判断与处理 |
|---|---|---|
| 找到正确内容，却漏了解释或条件 | T12遗漏正常保护解释；T57没收到版本就结束。 | 系统应改。不是继续多检索几篇就能解决。 |
| 已执行一部分，正在等必要事实 | T19/T38等密封圈观察，T26第三方清洁液，T40外链试验是否做过，T46异响类型。 | 停下来合理。测试不能替客户编造观察结果。 |
| 搜到了，但不适合当前对象或症状 | T52问充电盒自身，候选主要讲盒给泵充电；T61是提前启动，候选是无法启动。 | 不执行是正确边界；应追问或转人工，不能为提高“执行率”硬套。 |
| 官方资料没有覆盖或正文支撑不足 | T13没有5116；T37标题覆盖满水误报但正文主要是加水重启；T61缺对应完整指导。 | 知识负责人补资料。Agent可以说明不确定，不能编造型号专属答案。 |

本地错误码可以直接命中知识，因此“远程检索次数为0”也不等于没有用知识。每案记录都区分了已采用、仍在追问、不适用和缺资料。

## Agent该做到哪里，哪里必须交接

这里的Agent是代表系统理解问题、查资料、组织步骤和收集材料的助手。本项目业务材料没有提供真实订单变更或工单执行API，因此本轮的查单、方案和内部案件，不能当作承运商调查、仓库发货、退款或人工审核已实际完成。

- T1—T10物流问题：核对包裹和状态、提出调查或补寄方案合理。T2还存在“后台主机箱”和“客户收到配件”之间的数据冲突，应保留两方信息，交业务核实。
- T44、T49、T55更换诉求：收凭证、序列号和故障材料合理；在保也不等于已经换货。T55现有附件是订单，继续索要故障照片或视频有必要。
- T45烫伤：系统停用、停止充电并转内部人工，方向正确。测试不应为了走完普通排障再让客户试加热。
- T59跨型号置换、T63买配件：助手不能自行保证可换型号或有库存。T63已把关联故障一起留在交接摘要，不能因为转人工就说全漏了。

主轮最终停在以下位置，合计63案：

| 停点 | 数量 | 后面还需要什么 |
|---|---:|---|
| 等订单或购买凭证 | 26 | 客户提交材料后继续核验。 |
| 等自由文本、其他材料或选择 | 15 | 补充真实事实，不能由测试器猜。 |
| 等确认方案 | 7 | 客户确认后才继续申请流程。 |
| 等具体检查问题的答案 | 5 | 如密封圈情况、是否加过清洁液。 |
| 内部人工队列 | 5 | T9、T13、T45、T61、T63，状态仍待审核，未证明有人处理。 |
| 会话流程标记结束 | 5 | T2、T29、T35、T47、T51；包含正常机制解释、过保边界或缺另一张订单，并非5个故障修复。 |

## 图片和官方口径分别怎么看

本轮上传的10张原图均人工核对过。T30主机、T20仅有基站、T48泵体等主体判断已有可用结果；T42细节归属和T48动态灯态推断仍需改。发票、订单截图只是购买材料，不能证明设备损坏，也不能据此宣布凭证识别全链路准确。

官方口径指品牌确认的保修、临时方案、已知问题和产品专属解释。以下需要业务或知识负责人维护，不能靠模型常识代替：

- **T53：** 首次故障在保内、申请时过保，是否允许例外审核。系统要承接诉求，规则由官方定；客户口述“24个月”与订单日期也不能混为已核实事实。
- **T57：** 资料中的“App 5.0以上已知问题”适用哪些版本、型号和时间。不能长期无条件套用。
- **T32：** 胶带临时固定来自本地官方资料，本轮没有再说“成功率高”或提前承诺换新。仍应维护适用条件、使用期限和客户拒绝后的路线；本轮没有证据证明方案本身错误。
- **T48：** 绿灯确切含义需要型号与灯位匹配的可读官方资料。本轮核查未得到足以确认的答案，不作猜测。
- **T46/T51：** 部分旧候选资料有不合适或不清晰的部件术语，但本轮未向客户发出这些步骤。列为资料清理线索，不算成本轮实际错误。

## 建议下一轮先改和验证什么

1. 先修T50/T53的原话保真、T57的信息收集卡、T41的并列诉求。它们会直接改变处理对象或让流程提前结束。连同10案语言问题一起验收。
2. 再修T12解释与条件保留、T31已做步骤承接、T34恢复旧图路线；复测需提供真实分支答案，确认后续不会绕回同一个错误。
3. 图片验收分别检查“是哪件物体”“细节属于谁”“能否由单张图判断动态状态”，用T42/T48复测。
4. 官方补5116、满水误报、C20排程与记录、灯态表，并确认保修例外和App已知问题口径。系统只在这些边界内回答。

本轮完成的是测试、取证与判断，没有修改业务实现、发布版本或创建真实补寄／退款。本次结论按当前运行结果重新作出；旧记录只用于定位线索和复用逐字相同回复的译文，没有继承旧的通过结论。
