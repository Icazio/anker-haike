# 复评与结果

## 确认的原因

本机查询与 Vite 转发只需几十毫秒，云端通过 SSH 隧道获取 176034 字节案件队列只需 0.182 秒；公网同一响应需要 4.246–6.078 秒。慢主要发生在云端到访问网络的下载阶段，响应未压缩放大了等待。会话页和工作台都读取案件队列，因此均受影响。

## 已实施方案

在 Caddy 按 JSON、HTML、JS、CSS、SVG 的响应类型启用 zstd/gzip 压缩。事件流继续透传；认证、身份转发、HTTPS 和回环监听保持原有配置。本轮不需要提高实例规格或修改数据库查询。

| 公网请求 | 修复前传输字节 | 修复后 gzip 字节 | 修复后耗时 |
| --- | ---: | ---: | ---: |
| 会话 limit30 | 19539 | 3962 | 0.337 秒 |
| 会话 limit100 | 66874 | 11575 | 0.952 秒 |
| 案件队列 | 176034 | 21685 | 0.390–0.740 秒 |

修复前带 `--compressed` 的队列最小复现也返回未压缩的 176034 字节、耗时 2.263 秒；修复后同一命令低于原 2 秒门槛。公网延迟存在波动，上表是本轮测量样本，不是时延保证。

- `make -f deploy/tunnel/Makefile check`：通过。
